### UX Принципы (обязательно соблюдать)

#### Навигация и структура
- **Правило 3 кликов**: Любая информация не глубже 3 кликов от главной
- **Хлебные крошки**: На всех страницах глубже 2 уровня
- **Активное состояние**: Всегда показывать где находится пользователь
- **Понятные URL**: `/dashboard/widget-settings` лучше чем `/d/ws`

#### Формы и валидация
- **Inline validation**: Проверка при вводе, не после submit
- **Понятные ошибки**: "Пароль должен содержать минимум 8 символов" вместо "Invalid password"
- **Прогресс**: Показывать шаги если форма длинная (1 из 3, 2 из 3...)
- **Автофокус**: Первое поле формы получает фокус автоматически
- **Disabled state**: Кнопка "Сохранить" неактивна пока форма невалидна

#### Обратная связь пользователю
- **Loading states**: Скелетоны вместо спиннеров где возможно
- **Success feedback**: "✓ Сохранено" на 2 секунды после действия
- **Error recovery**: Предлагать решение, а не просто "Ошибка"
- **Пустые состояния**: Красивая заглушка + CTA когда нет данных

#### Микроанимации (обязательные)
- **Hover states**: Все интерактивные элементы реагируют на наведение
- **Button feedback**: Scale 0.98 при клике (тактильное ощущение)
- **Transitions**: Плавное появление/скрытие (200-300ms ease-out)
- **Focus states**: Видимый outline для keyboard navigation

#### Мобильная адаптивность
- **Touch targets**: Минимум 44×44px для кнопок
- **Отступы**: Минимум 16px от краёв экрана
- **Шрифты**: Минимум 16px для основного текста (иначе iOS зумит)
- **Модалки**: На мобильных открываются на весь экран

## Качество кода

### Принципы кода
- **DRY**: Не дублировать логику
- **KISS**: Простые решения лучше сложных
- **Компонентный подход**: Маленькие, переиспользуемые компоненты
- **TypeScript строго**: Никаких `any`, использовать интерфейсы
- **Комментарии**: На русском, объясняют "почему" (для сложной логики и общих выводов), а не "что"
- **Именование**: Понятное, описательное (не сокращения)

### Обязательные практики
- Server Components по умолчанию (Next.js)
- Client Components только где нужна интерактивность
- Error boundaries для всех роутов
- Loading states везде где async операции
- Валидация форм: React Hook Form + Zod
- API: всегда возвращать структурированные ошибки
- Безопасность: sanitize пользовательский ввод
- SEO: метатеги для всех публичных страниц

### Производительность
- Ленивая загрузка изображений (next/image)
- Code splitting автоматически (Next.js)
- Минимизация bundle size (проверять)
- Кэширование API запросов где уместно
- Оптимизация шрифтов (next/font)

### Архитектура кода

#### Структура компонентов
```typescript
// ❌ ПЛОХО: всё в одном файле
export default function Dashboard() {
  const [data, setData] = useState();
  // 500 строк кода...
}

// ✅ ХОРОШО: разделение ответственности
export default function Dashboard() {
  return (
    <DashboardLayout>
      <StatsCards />
      <RecentChats />
      <QuickActions />
    </DashboardLayout>
  );
}
```

#### Правило одной ответственности
- **Компонент**: 1 компонент = 1 задача (максимум 200 строк)
- **Функция**: 1 функция = 1 действие (максимум 30 строк)
- **Файл**: 1 файл = 1 экспорт (кроме утилит)

#### Типизация (строго!)
```typescript
// ❌ ПЛОХО
const handleSubmit = (data: any) => { ... }

// ✅ ХОРОШО
interface FormData {
  email: string;
  password: string;
}
const handleSubmit = (data: FormData) => { ... }
```

#### Именование (консистентность)
- **Компоненты**: PascalCase (`UserProfile.tsx`)
- **Хуки**: camelCase + "use" префикс (`useAuth.ts`)
- **Утилиты**: camelCase (`formatDate.ts`)
- **Константы**: UPPER_SNAKE_CASE (`MAX_FILE_SIZE`)
- **Типы/Интерфейсы**: PascalCase (`type User = ...`)

#### Error Handling (везде!)
```typescript
// ✅ ОБЯЗАТЕЛЬНО оборачивать в try-catch
async function fetchData() {
  try {
    const data = await api.get('/users');
    return { success: true, data };
  } catch (error) {
    // Вывод: логируем ошибку для разработчика
    console.error('Failed to fetch users:', error);

    // Показываем понятное сообщение пользователю
    toast.error('Не удалось загрузить данные. Попробуйте позже.');
    return { success: false, error };
  }
}
```

#### Производительность (мониторить!)
- **Bundle analyzer**: Запускать перед каждым релизом
- **Lighthouse**: Минимум 90 на Production
- **React DevTools Profiler**: Проверять рендеры компонентов
- **Мемоизация**: `useMemo`/`useCallback` для тяжёлых вычислений

```typescript
// ✅ Мемоизация тяжёлых вычислений
const sortedUsers = useMemo(() =>
  users.sort((a, b) => a.name.localeCompare(b.name)),
  [users]

```

## Доступность (A11y) - обязательные требования

### Семантика HTML
- **Заголовки**: H1 → H2 → H3 (без пропусков уровней)
- **Landmarks**: `<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`
- **Кнопки vs ссылки**: `<button>` для действий, `<a>` для навигации
- **Labels**: Каждый input имеет связанный `<label>`

### Keyboard Navigation
- **Tab order**: Логичный порядок обхода (сверху вниз, слева направо)
- **Focus trap**: В модалках Tab не выходит за пределы
- **Skip links**: "Перейти к содержимому" для screen readers
- **Escape key**: Закрывает модалки и дропдауны

### ARIA (когда нужно)
```tsx
// Только если семантика HTML недостаточна
<button
  aria-label="Закрыть модальное окно"
  aria-expanded={isOpen}
  aria-controls="menu-dropdown"
>
  ✕
</button>
```

### Контраст и цвета
- **WCAG AA**: Минимум 4.5:1 для обычного текста
- **WCAG AA**: Минимум 3:1 для крупного текста (18px+)
- **Не только цвет**: Ошибки показывать через иконку + цвет

### Тестирование доступности
- **axe DevTools**: Проверять каждую страницу
- **Keyboard only**: Проходить весь флоу без мыши
- **Screen reader**: Проверять в NVDA (Windows) или VoiceOver (Mac)

## Процесс разработки

### Процесс разработки фичи

1. **Планирование** (перед кодом!)
   - Понять задачу полностью
   - Спросить если что-то непонятно
   - Предложить альтернативы если есть

2. **Дизайн** (если UI компонент)
   - Показать мокап или описание
   - Получить подтверждение
   - Только потом писать код

3. **Разработка**
   - Писать чистый, понятный код
   - Комментировать сложные места и общие выводы (на русском)
   - Следовать принципам выше

4. **Самопроверка** (перед показом)
   - Код работает без ошибок в консоли
   - Адаптивность (320px, 768px, 1920px)
   - Keyboard navigation работает
   - Lighthouse > 80

5. **Коммит**
   - Осмысленное сообщение на русском
   - Один коммит = одна логическая единица

## Виджет записи

### Требования
- **Минимальный вес**: <50KB сжатого JS (если это будет возможно)
- **Изоляция**: Не конфликтует с клиентским сайтом (Shadow DOM)
- **Настраиваемость**: Цвета, шрифты через параметры
- **Sticky поведение**: Привязка к скроллу где нужно
- **Статичное размещение**: Возможность фиксированной позиции
- **Адаптивность**: Работает на всех разрешениях
- **Доступность**: Работает без JS (graceful degradation)
